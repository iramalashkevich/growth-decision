## 5. Риски дизайна — чек-лист перед стартом

- [ ] Тест покрывает полный цикл активности пользователя и целое число недель
- [ ] Период не попадает на праздники / распродажи / крупный релиз / сезонный пик
- [ ] Нет сетевых эффектов и спилловера между группами (иначе — switchback / гео-сплит)
- [ ] Проведён A/A или система сплитования проверена ранее
- [ ] Логирование одинаково работает в обеих ветках
- [ ] Целевая метрика одна; для остальных заранее принята поправка на множественность
- [ ] Пользователь жёстко закреплён за вариантом (нет перетекания)
- [ ] План проверки SRM перед анализом

## 6. Решения при каждом исходе (заполнить ДО старта)

| Исход | Что делаем |
|---|---|
| Эффект ≥ MDE, значим, guardrail ок | раскатываем на 100% |
| Значим, но < MDE | не раскатываем; фиксируем как отрицательный результат |
| Не значим, ДИ целиком ниже MDE | гипотеза опровергнута, направление закрываем |
| Не значим, ДИ шире MDE | мощности не хватило — добираем данные / переделываем тест |
| Целевая ↑, guardrail ↓ | разбираем побочный эффект до любого решения |
| Отрицательный эффект | откатываем; разбираем механизм — это тоже знание |
